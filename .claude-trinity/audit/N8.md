**② 事务内兜底守卫保留，但改为落终态**

- 新增三个终态哨兵：`ErrPlanPurchaseCapReached` / `ErrPlanQuotaInvalid` / `ErrPlanQuotaOverflow`
  + `isPlanCreditTerminal(err)`。哨兵文案本身即用户可读中文，不套 `%w` 包装，
  所以 `PurchaseSubscriptionWithBalance` 那条余额路径的报错文案零变化。
- 新增 `failSubscriptionOrderTx`：订单置 `common.TopUpStatusFailed` + `CompleteTime` + 同步分销台账。
- 新增 `settlePaidOrderTx` + `subscriptionSettlement`：终态被命中时把 rejection 记在 settlement 上、
  **提交 failed 状态**（不再整体回滚成 pending），事务提交后
  `common.SysLog("订阅订单已收款但额度入账被拒，订单已置失败需人工退款 trade_no=... reason=...")`。

**关于返回值的取舍（明确记录）**：兜底命中后 `CompleteSubscriptionOrder` 仍返回该 rejection，
不伪造成功。理由：返回 nil 会让 epay/xunhu 回调写 `success`、`SubscriptionEpayReturn` 跳
`?pay=success`，用户看到一个假的成功页。返回 error 后网关重试也不再是「每次都从头收钱」——
订单已是 failed 终态，重试直接被 `loadPendingSubscriptionOrderTx` 判 `ErrSubscriptionOrderStatusInvalid`，
是既有的廉价空转，且 SysLog 已明确点名需要人工退款。

**关键点**：所有终态拒绝都排在第一次写之前（`TotalAmount` → 上限 → 溢出 → 升组 → 加额度），
所以「提交 failed」这一步不会把半截写入一起提交。

**新增测试**：`TestCompleteSubscriptionOrder_SettlesOrderFailedWhenCapReached`
（断言 `ErrorIs` 哨兵 + 订单落 failed + CompleteTime 非零 + 额度一分未加 + 没有伪造 top_ups 行）。

### F2 · GORM v2 假锁 ✅ 已修（只修本轮订阅购买链路）

  限购 COUNT 的并发穿透与「余额读-判-写」竞态一并堵住。
- 函数注释已改写：明说这是 `clause.Locking` 的真锁，并点名 `gorm:query_option` 在 GORM v2 下是 no-op。
- **未动**（主控裁决另开工单）：`model/topup.go` ×6、`model/user.go:356`、`model/redemption.go:130`、

### F3 · 溢出守卫 ✅ 已加（防御性，不依赖生产列宽结论）

- 新增 `walletQuotaCeiling()`：读 `USER_QUOTA_CEILING`（`common.GetEnvOrDefault` 既有 seam），
  默认 `math.MaxInt64` —— 即默认只防 int64 加法溢出，**不会误伤已有的大额账户**
  （交接文档里管理员 ≈5e13 quota 照常可用）。若生产核实下来 `users.quota` 真是 4 字节，
  运维把该环境变量设成 `2147483647` 即可，无需改代码。
- 新增 `ensurePlanQuotaFits(currentQuota, amount)`：负余额先夹到 0 再算 headroom
  （否则 `MaxInt64 - 负数` 自己就溢出了），超限返回 `ErrPlanQuotaOverflow`。
- 挂在 `CreditPlanQuotaTx` 的加额度之前，且它是终态哨兵之一 → 命中时走 F1 的
  「订单置 failed + 告警」路径，**不会退化成「钱收了订单卡 pending」**。
